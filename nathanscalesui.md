# Nathan Scales — UI System & Visual Direction

## Design Intent

Nathan Scales should look like a **serious independent digital studio that combines design, development, marketing, and software systems**.

The visual identity is intentionally monochrome.

The design should communicate:

**precision + competence + clarity + restraint**

Not:

**AI startup + flashy agency + generic SaaS template**

---

# 1. Visual Personality

Use these qualities as the design filter:

- black and white
- editorial
- technical
- sharp
- spacious but not empty
- asymmetric where useful
- structured
- quiet confidence
- portfolio-driven
- business-oriented
- premium through composition, not decoration

The site should feel like a designer/developer cared about every decision.

---

# 2. Color System

## Primary

Use a restrained monochrome palette.

### Black
`#0A0A0A`

Use for:

- main background
- navigation
- strong panels
- footer
- dominant visual areas

### White
`#FFFFFF`

Use for:

- primary text on black
- buttons where appropriate
- clean negative-space areas
- high-contrast surfaces

### Off White
`#F5F5F2`

Use sparingly for:

- light sections
- reading surfaces
- contrast breaks

### Neutral Gray
`#A3A3A3`

Use for:

- metadata
- secondary copy
- technical labels
- subdued UI

### Dark Gray
`#1A1A1A`

Use for:

- elevated black surfaces
- subtle panel separation
- code/interface-like areas

Do not introduce accent colors.

Do not use:

- purple
- blue
- pink
- neon green
- orange gradients
- rainbow effects

Do not use gradients as a visual crutch.

---

# 3. Typography

Do not use a default font pairing simply because it is common.

Choose a deliberate grotesk/sans-serif type system available to the project.

Recommended hierarchy:

### Display
Large, strong sans-serif.

Use for:

- hero headline
- major section statements
- featured project names

Characteristics:

- tight but readable tracking
- controlled line length
- strong contrast in scale

### Body
Neutral highly readable sans-serif.

Use for:

- paragraphs
- service descriptions
- navigation
- form framing
- supporting UI copy

### Technical / Metadata
Monospace optional.

Use for:

- section numbers
- project metadata
- category labels
- small interface labels

Do not overuse monospace.

---

# 4. Layout Grid

Use a consistent max-width container.

Suggested structure:

- large desktop: 12-column logic
- tablet: 8-column logic
- mobile: 4-column logic

Use consistent outer margins.

Desktop should feel composed, not centered in an oversized empty rectangle.

Preferred content widths:

- copy: narrow enough to remain readable
- project media: allowed to become wide
- hero composition: asymmetric
- section headings: can span multiple columns

---

# 5. Spacing System

Use a consistent spacing rhythm.

Suggested baseline:

- 8px
- 12px
- 16px
- 24px
- 32px
- 48px
- 64px
- 96px
- 128px

Do not use huge spacing between every section simply to mimic luxury websites.

Spacing should reflect hierarchy.

---

# 6. Shape Language

Keep shapes restrained.

Prefer:

- square or lightly rounded corners
- thin borders
- rectangular project frames
- clean rules

Avoid:

- huge rounded cards
- pill-shaped everything
- floating glass panels everywhere
- excessive shadows

Buttons may use modest radius or square geometry.

Cards should not all have exactly the same visual treatment.

---

# 7. Header

Recommended structure:

Left:
**Nathan Scales**

Center/right:

Work
Services
Process
About

Far right:
**Start a Project**

Desktop header can be compact and slightly separated from the main hero.

Use a thin line or subtle structural boundary rather than a giant navigation panel.

Mobile navigation:

- logo/name
- compact menu trigger
- strong Start a Project action

Do not use an overly elaborate mega-menu.

---

# 8. Hero Layout

Avoid the generic centered SaaS hero.

Use an asymmetric composition.

Suggested desktop composition:

Left column:
small eyebrow / descriptor
large headline
short supporting copy
primary CTA
secondary work link

Right / lower composition:
actual project/interface visual or typographic system

Possible eyebrow:

`DIGITAL STUDIO / WEB / GROWTH / SOFTWARE`

Hero headline should be large but not cartoonishly oversized.

A possible copy direction:

**Websites, marketing, and software built around your business.**

Do not blindly copy this exact line if the existing site's real positioning suggests stronger copy.

The headline must communicate the business value clearly.

---

# 9. CTA System

Primary CTA label:

**Start a Project**

Secondary:

**View Work**

Primary CTA behavior:

- opens the Google Form in the current site
- no new tab
- no redirect to another website
- preserve current scroll position when the form closes

Hover:

- small horizontal translation
- subtle background/fill transition
- no glow
- no dramatic scale

---

# 10. Project Visual Treatment

Projects should be the strongest visual proof.

Use real project assets.

Project blocks should feel like editorial case-study fragments.

Possible project layout:

### Featured project
Large media block
Project name
Category
Short description

### Secondary project
Medium media
Project name
Category

### Supporting project
Smaller block
Metadata
Description

Do not make every project identical.

Use different aspect ratios and layout relationships.

Hover can reveal:

- project category
- "View project" label
- movement of an arrow indicator
- subtle image zoom

Avoid flashy hover overlays.

---

# 11. Services Visual Treatment

Do not use three identical rounded cards.

Instead, use a structured list or editorial rows.

Example:

`01 / WEBSITES`

Large heading.

Description on the right.

Capabilities below as a compact list.

Then:

`02 / DIGITAL MARKETING`

Then:

`03 / CUSTOM SOFTWARE`

Each service can have a distinct visual rhythm.

Use borders, rules, numbering, and typography to create hierarchy.

This will feel more like a studio practice than a SaaS component library.

# 13. Process Section

Use a horizontal or vertical timeline instead of card stacks.

Example:

`01`
Understand

`02`
Structure

`03`
Build

`04`
Refine

`05`
Launch

Each step gets a concise sentence.

Use a visible line connecting the steps.

On mobile, turn the timeline into a vertical progression.

Motion:

- line draws/reveals
- current step subtly activates
- content enters with short upward motion

No spinning indicators.

# 15. About Section

Keep this concise.

Purpose:

Answer:

**Who is behind the work, and how does the work get done?**

The about area should feel personal enough to build trust but not like a corporate biography.

Use actual information from the repository/site.

Do not create fake credentials.

Visual treatment:

- typography
- portrait only if an actual real portrait exists
- concise philosophy
- technical/business positioning

---

# 16. Final CTA Section

Use a strong black section near the bottom.

Suggested heading direction:

**Build the next part of your business.**

Supporting text should explain what the visitor can submit through the form.

CTA:

**Start a Project**

Secondary small text:

`Tell me what you're trying to build, fix, improve, or automate.`

This final section should be visually simple.

Do not add a giant background illustration.

# 17. Footer

Include:

Start a Project.

Relevant contact/social links only if real information exists.

Do not invent:

- social accounts
- phone numbers
- addresses
- email addresses

# 18. Motion Guidelines

Use CSS/Framer Motion/GSAP only if already present or clearly useful.

### Page-load motion

- headline enters
- supporting copy enters slightly later
- CTA enters
- hero visual reveals

### Scroll motion

- section text rises subtly
- project media reveals
- process line progresses

### Hover motion

- CTA shifts
- project image moves slightly
- navigation state changes
- service row responds

### Modal motion

- backdrop fades
- form frame rises slightly
- close control appears

Motion durations:

- fast: 150–200ms
- normal: 250–400ms
- slow: 500–700ms

Avoid everything moving for 1 second.

Respect `prefers-reduced-motion`.

---

# 19. Buttons

Buttons should look like designed controls rather than default Tailwind/shadcn components.

Primary:

- strong black/white contrast
- clear label
- modest radius
- enough padding
- obvious hover

Secondary:

- understated outline/text interaction

Do not use five button styles on the same page.

---

# 20. Dividers and Rules

Use thin lines strategically.

Good uses:

- section boundaries
- service rows
- process timeline
- navigation separation
- project metadata

Lines should reinforce structure.

Do not box every component.

---

# 21. Responsive Behavior

Desktop:

- asymmetric layouts
- stronger editorial composition
- wide project imagery
- side-by-side content

Tablet:

- reduce column complexity
- preserve visual rhythm

Mobile:

- stack intelligently
- maintain large type
- avoid everything becoming cards
- keep project previews visually strong
- preserve CTA prominence

The mobile UI should look intentionally designed, not like the desktop version got squashed.

---

# 22. Accessibility

Required:

- semantic landmarks
- readable contrast
- keyboard navigation
- visible focus states
- accessible modal
- correct heading hierarchy
- descriptive alt text for actual images
- form close control
- reduced motion support

---

# 23. Anti-Slop Checklist

Before considering the visual design finished, verify:

### No AI-template tells

- no purple gradient
- no gradient text
- no neon glow
- no emoji icons
- no fake testimonial cards
- no fake client logos
- no fake metrics
- no centered generic hero
- no hero followed immediately by three feature cards
- no cream/serif/sage "AI tasteful" replacement
- no excessive glassmorphism
- no repeated giant rounded cards
- no random decorative blobs
- no excessive pills
- no meaningless bento layout

### Human design signals

- clear visual system
- distinct composition
- real work shown
- useful metadata
- deliberate typography
- strong hierarchy
- varied section composition
- whitespace with purpose
- restrained motion
- clear CTA

# 24. Final Visual Standard

The finished website should feel like:

**A small, capable digital studio that can be trusted with a business-critical website, marketing system, or custom software project.**

It should not feel like:

**A person typed "make me a premium AI agency website" into an AI builder.**

Every visual decision should answer one of three questions:

1. Does this improve trust?
2. Does this clarify the offer?
3. Does this move the visitor toward starting a project?

If it does none of those, remove it.
